Rendering real articles is left to `e2e.mjs`, so run that before a release; the offline test is for when the wiki is down, or for a quick check.

Random play is a seeded run of 30 steps on one pair: link clicks (sometimes a second while the first loads), Back (sometimes during a load), theme switches, peeks and path toggles. After each step the game has to settle with the click count, the path list, the Back stack, the article shown and the clock agreeing. The seed is printed with the result, and `MWR_SEED=<seed> test/run-e2e.sh` replays the same choices, though the wiki may have changed since. It needs `firefox` and Node ≥ 22 (for the global `WebSocket`), plus network access. Headless Firefox has no pointer device and matches `(hover: none)`, so `run-e2e.sh` sets `ui.primaryPointerCapabilities` to report a mouse, as a desktop browser does. It runs as a single script; to focus on one behavior, edit or comment out checks in `e2e.mjs`. Code inside the article iframe is evaluated in the frame's own browsing context (`frameCtx()`).

The offline suite runs before every commit as a git pre-commit hook, `.githooks/pre-commit`, turned on once per clone with `git config core.hooksPath .githooks`. It tests the working tree, prints only the failures and the summary, and stops the commit if a check fails (`git commit --no-verify` skips it, for a commit that can't run Firefox). It uses port 9335, so a live suite running at the same time keeps its Firefox. The live suite runs only by hand, and there is no CI, so the live wiki can change between runs unnoticed. Before a release, run it, then check by hand what neither suite can: the game in Chrome (the suites only drive Firefox) and in Safari on an iPhone (the 16 px inputs not zooming, the `100dvh` layout under the toolbars, no leave-page dialog there), how real articles look (glance at the screenshots `run-e2e.sh <dir>` saves, and a few articles in both themes for a new wiki widget that needs the wiki's own script, as the calculators did), that the sounds play and the mute works, the items by hand (see [items.md](items.md): a blast on a scrolled setup screen and article, the pieces resting on the page and none of it growing or scrolling sideways, the page untouchable but scrollable while broken, the shake leaving the buttons and toys in place, Rebuild smooth, the creeper and ghast facing their way, the textures and toasts), and a game or two on a real phone, upright and on its side.
