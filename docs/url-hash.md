# URL hash keys

The game reads these keys from the URL hash (`init`), and leaves any other out:
- `g=<blob>`: a sealed challenge link, what "Copy challenge link" (`challengeLink`, through `gameLink`) makes, on the setup screen and in the result, for any game but a daily, whose link is its `daily=`. It is the query the keys below would make (`challengeQuery`), sealed (`sealLink`) so the URL doesn't give the pair, or Blind target's hidden cards, away at a glance: a random 4-byte nonce, then the query's UTF-8 and its `hash32` XORed with a mulberry32 keystream seeded by `LINK_KEY` and the nonce, in base64url. That only hides it from a glance, since the key is in the page. So `openLink` gives back the plain query, which `init` reads with the same code and checks as a hand-made link, and the blob holds the setup only (never a daily, par or result): a made-up blob can do nothing a plain link can't. A `#g=` hash is read on its own, leaving anything beside it out. A blob longer than `LINK_MAX` (room for five titles of MediaWiki's longest), not base64url or failing its hash (a link a chat app cut short) rolls a random pair and says the link is damaged.
- `start=<Title>` with `target=<Title>` (or `kind=`): a fixed pair, handy for testing a specific route. A `start` with neither is no challenge, and a pair is rolled. Every title is looked up live, and if one doesn't exist a random pair is rolled instead. A sealed link's missing article isn't named in the message, since anyone can seal any text in a link and titles are otherwise only shown once the wiki has them; a hand-made link's is, its titles being in the URL to read.
- `via=<Title>`: a checkpoint, in order, up to three, which turns the Checkpoint rule on with that count. With Scavenger in `rules`, the target and the `via=` titles are its three articles instead.
- `back=N`: with Round trip, how many of the checkpoints come after the target, on the way back (missing or out of range, it is moved to the nearest that fits).
- `extra=N`: with Exact clicks, how many clicks over par the count is (one of `EXACT_EXTRAS`, 1 to 5; others are left out, and without one the strip keeps par + 2). It holds the number, never the count, which comes from par, and a Random game's link holds the number it rolled. Under Blind target a challenge's number is held unseen like its cards: the strip shows Random, since the opener can't know it, with the link's number in `setup.extra`, and the next roll of the cards rolls a new one. Like `rules`, it is read for a rolled pair too, where it is shown.
- `kind=<Category>`: in place of `target` (a link with both plays the kinds), one of Scavenger's kinds (a `KINDS` key; others are left out), up to three, which turns Scavenger on with kinds.
- `rules=<key>,<key>`: rule keys (`RULES`; others are left out), the difficulty included (`setRules`: `nonav` is Normal, `nonav,nohubs` or `nohubs` alone Hard). A challenge link always sets them, so one without `rules` is Relaxed, as every game was before difficulty. They are applied even if the pair fails to load. On its own, `#rules=…` sets them for a rolled pair.
- `daily` and `daily=YYYY-MM-DD`: today's daily pair and rule, or a past day's (a challenge pair beside it wins, and the day's rule replaces `rules`). Only a real day that has come plays (`dailyDate`, by the player's local date): one that is malformed, doesn't exist (`realDate`: 2026-02-31, or a year below 100, which `Date.UTC` reads as 19xx) or hasn't come yet loads today's instead, so nobody can practise a daily before its day.
